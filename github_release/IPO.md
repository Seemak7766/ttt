# 여행 챗봇 IPO 명세

| 입력 | 처리 | 결과 |
| --- | --- | --- |
| 지역·방문 조건이 있는 장소 질문 | 모델이 지역(region), 장소 종류(place_type), 방문 조건(visit_conditions)을 도구 인자로 전달합니다. 검색 결과를 ToolMessage로 모델에 다시 전달합니다. | 실제 조회한 장소를 번호 목록으로 표시하고, 굵은 장소명 아래 주소·분류·지도 링크를 안내합니다. 실행 기록에 도구·인자·status·결과 수를 남깁니다. |
| 날짜가 없는 장소 질문 | 장소 검색에는 날짜가 필요 없으므로 날짜를 추가로 묻지 않고 검색합니다. | 장소를 바로 안내합니다. 지역이 불분명한 경우에만 지역을 묻습니다. |
| 단순 인사 | 인사만 있는 입력은 코드에서 판별해 모델·검색 도구 없이 응답합니다. | 인사 답변과 장소 도구 호출 0회 기록을 보여줍니다. |
| 기존 대화의 후속 장소 질문 | 선택한 대화의 이전 메시지를 그대로 모델에 전달합니다. | 대화별 기억·목록·날짜·지도 링크 기능을 유지합니다. |

실행 방식은 자동으로 판단하며 선택 메뉴는 없습니다. 답변 아래 ‘실행 결과 (IPO)’에서 호출 횟수/한도·인자·status·반환 장소·실행 순서를 확인합니다. 기록은 대화와 같은 브라우저 세션에만 보관하며, 인증 헤더·API 키·원본 예외는 기록하지 않습니다.

## 실행 순서와 비교

아래 비교 기능은 코드 검증용입니다. 사용자 화면에는 선택 메뉴나 두 실행 비교 화면을 표시하지 않습니다. 실제 대화는 자동 재검색 모드로 실행하고 해당 실행 결과를 보여줍니다.

| 입력 | 처리 | 결과 |
| --- | --- | --- |
| 한 번의 에이전트 실행 | `tool_call → tool_return → next_call 또는 answer` 순서를 step 번호로 남깁니다. 내부 사고 전문은 저장하지 않습니다. | 답변 아래 실행 기록에 도구 이름·인자·status·반환 장소를 표시하며 제목에 호출 횟수/한도를 표시합니다. |
| 같은 요청의 1회 종료 실행과 재검색 실행 | ‘두 방식 비교’에서 같은 질문·대화 맥락·첫 검색 인자로 각각 실행합니다. | 두 답변과 기록을 나란히 보며 무엇을 다시 검색했는지, 왜 재검색했는지, 언제 종료했는지 기록 값으로 확인합니다. |
| 답변과 기록의 근거 일치 | 마지막으로 실행한 도구 반환만 최종 장소 안내에 사용합니다. | 답변의 장소는 마지막 도구 반환의 장소와 일치합니다. 이전 호출의 다른 장소는 최종 답변에 섞지 않습니다. |

- **1회 종료:** 장소 도구 최대 1회. 반환 후 답변합니다.
- **재검색:** 최대 3회. `no_results`일 때만 다른 검색어로 재검색하며, 성공·오류·한도 도달 또는 모델의 도구 미호출 시 종료합니다.
- **두 방식 비교:** 같은 첫 검색 인자로 각각 실행합니다. 첫 검색이 성공하면 양쪽 모두 1회에 종료될 수 있습니다. 대화 기록은 두 실행이 끝난 후 한 번만 갱신하며, 후속 대화는 재검색 실행의 답변을 기준으로 합니다(해당 실행 실패 시 성공한 실행 사용).
- 도구 내부 자동 재검색은 끄므로 실제 장소 HTTP 요청도 도구 호출 1회당 1회입니다. `no_results_retry`, `search_succeeded`, `call_limit` 같은 관찰 가능한 전환·종료 사유만 남깁니다.
- 과거 대화는 당시 답변과 기록을 그대로 보관합니다. 새 실행부터 비교·순서 기록·마지막 반환 기준이 적용됩니다.

장소 API의 응답에는 주차·반려동물 동반·현재 영업 여부 같은 조건이 포함되지 않습니다. 방문 조건은 기록하고 모델에 전달하지만 충족 여부를 확인했다고 표시하지 않습니다.

검색 status: `ok`, `no_results`, `empty_query`, `missing_key`, `auth_error`, `quota_error`, `unavailable`. 도구 실행 전 차단: `limited`, `invalid_tool_call`.

## 날씨 IPO

| 입력 | 처리 | 결과 |
| --- | --- | --- |
| 지역과 상대 날짜가 있는 날씨 질문 | 한국 시간 날짜 해석 → 카카오 장소 검색 → 반환된 x=경도·y=위도로 Open-Meteo 조회 | 날짜(요일), 최고·최저 °C, 일별 최대 강수확률 %. 마지막 날씨 결과를 답변 근거로 사용하고 출처·조회 시각을 기록합니다. |
| 날짜 없는 날씨 질문 | 외부 API 없이 날짜를 확인합니다. | 날짜를 다시 묻습니다. status=date_required. |
| 과거·예보 범위 밖 날짜 | 모델·장소·날씨·제목 요약 API를 호출하지 않습니다. | 예보 없음. 조회 시각은 null, 사전 검사 시각만 기록합니다. |
| 응답에 해당 날짜의 자료가 없음 | 해당 응답의 누락을 표시하고 추가 조회하지 않습니다. | 예보 없음. 일부 값은 정보 없음. 현재 날씨로 대체하지 않습니다. |
| 날씨와 장소 추천을 함께 요청 | 공유 지역 추출 후 날씨 작업과 추천 작업을 병행합니다. 날씨 작업 내부에서만 좌표 조회 → 예보 조회 순서를 지킵니다. | 날씨 표와 최대 3곳 추천 목록을 함께 표시합니다. 두 작업의 branch·출처·조회 시각과 섹션별 근거 호출 번호를 기록합니다. |

자료 누락은 유효 범위 내 요청의 응답을 받은 뒤에만 알 수 있습니다. 이 경우 이미 수행한 요청은 기록하고 추가 호출은 하지 않습니다.

참고: [Open-Meteo Forecast API](https://open-meteo.com/en/docs).

참고: [카카오맵 REST API](https://developers.kakao.com/docs/ko/kakaomap/rest-api), [LangChain ToolMessage](https://reference.langchain.com/python/langchain-core/messages/tool/ToolMessage).

날씨 답변에는 내부 상태값을 표시하지 않습니다. out_of_range 등은 실행 기록에만 남깁니다.

## 기능별 화면과 독립 실행

답변 본문은 날씨와 지역·장소 추천을 합친 하나의 글로 표시합니다. 본문 아래 실행 결과 탭만 날씨 왼쪽 50%, 지역·장소 검색 오른쪽 50%에 배치하며, 각 탭에는 해당 branch 기록만 표시하고 기본적으로 접습니다. 요청하지 않은 기능은 호출하지 않습니다.
복합 요청에서 날씨 날짜가 없거나 예보 범위 밖이면 날씨 API는 호출하지 않고 안내하며, 장소 추천은 별도로 진행합니다. 날씨만 요청했다면 기존처럼 모든 외부 API 호출을 생략합니다.
