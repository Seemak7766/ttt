# 여행 챗봇

Python 3.12.3, LangChain, OpenAI API, Streamlit으로 대화 맥락을 기억하는 여행 챗봇입니다.
왼쪽 ‘＋ 새로운 대화’ 버튼으로 대화를 추가하고, 목록에서 기존 대화를 선택해 이어갑니다.
각 대화는 독립된 기록을 가지며 선택한 대화의 이전 질문과 답변만 API에 전달합니다.
대화 제목은 전체 내용을 24자 이내로 요약하며, 답변을 받을 때마다 갱신합니다.
제목 요약을 위해 답변 후 추가 API 요청 1회가 발생합니다. 요약 실패 시 기존 제목을 유지합니다.
대화 제목 아래 작은 글씨로 마지막으로 답변받은 질문의 입력 날짜와 시간(한국 시간)을 표시합니다.
각 질문 말풍선 안의 오른쪽 끝에도 해당 질문의 입력 날짜와 시간을 표시합니다. 변경 전 기록은 시간을 추정하지 않고 '시간 기록 없음'으로 표시합니다.
여러 여행 선택지를 제안하거나 비교하는 답변은 Markdown 표로 정리하도록 지정했습니다.
대화 목록은 마지막 질문 시간순으로 정렬하며, 새 대화는 생성 시간을 기준으로 표시합니다.
여행과 무관한 질문에는 답하지 않고 여행 관련 질문을 요청하도록 시스템 프롬프트에 지정했습니다.
대화는 Streamlit 브라우저 세션에만 보관하며 새로고침, 연결 종료, 서버 재시작 시 사라질 수 있습니다.
디스크 저장과 일반 웹 검색은 사용하지 않습니다. 국내 장소 검색은 카카오맵 REST API를 사용합니다.
긴 대화는 모델의 입력 한도에 도달할 수 있습니다.

## 실행 (PowerShell)

Python 3.12.3 설치 후 아래 명령으로 가상환경을 만들고 실행합니다.

```powershell
py -3.12 -m venv .venv
Copy-Item .env.example .env
# .env에 본인의 API 키를 입력한 후 다음 명령을 실행하세요.
.\.venv\Scripts\python.exe --version
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m streamlit run app.py
```

`.env`가 없을 때만 `.env.example`을 복사하고 OPENAI_API_KEY 값을 입력하세요.
기존 `.env`는 보존했습니다. OPENAI_MODEL은 선택 사항이며 비어 있으면
config.py의 DEFAULT_MODEL(gpt-4o-mini)을 사용합니다. 설정 변경 후 앱을 재시작하세요.
터미널에 표시된 로컬 주소로 접속합니다. 종료는 Ctrl+C입니다.
실제 질문 요청에는 API 비용이 발생할 수 있습니다.
입력창에서 Enter를 누르면 바로 답변을 요청하고 Alt+Enter는 줄바꿈합니다.
한글 조합 중 Enter는 글자 확정에 사용되며 전송하지 않습니다. 답변 받기 버튼도 사용할 수 있습니다.

## 구성과 보안

- app.py: 대화 목록, 새로운 대화 버튼, 대화 기록과 질문 입력창
- static/keyboard_shortcuts.html: Enter 전송, Alt+Enter 줄바꿈과 한글 조합 보호
- chatbot.py: 선택한 대화 기록과 현재 질문 전달, 공백 입력 차단, 원본 오류 출력 금지
- config.py: .env 읽기와 별도 모델 설정
- prompts/travel_system.md: 여행 상담 시스템 프롬프트. 이 파일을 수정하면 다음 질문부터 반영됩니다.
- .env.example: 값 없는 변수 이름만 제공
- .gitignore: .env와 .env.* 제외, .env.example만 포함

이 배포용 폴더에는 현재 Streamlit 앱에서 사용하는 소스만 포함했습니다. 이전 server.py, 데이터베이스와 이전 웹 UI 파일은 제외했습니다.
새 앱은 반드시 streamlit run app.py로 실행하세요.
이미 Git에 추적된 비밀 파일은 .gitignore만으로 추적 해제되지 않습니다.

## 카카오맵 장소 검색

`.env`의 `KAKAO_REST_API_KEY`에 카카오 REST API 키를 설정하세요. 키는 서버에서 인증 헤더로만 전송하고 모델이나 화면에 전달하지 않습니다.
설정된 키가 없으면 기존 여행 상담만 제공합니다. `.env.example`에는 변수 이름만 포함되어 있습니다.

- ‘제주 애월 카페 찾아줘’, ‘부산 해운대 관광지 추천해줘’처럼 질문하면 모델이 필요할 때 국내 장소를 검색합니다.
- 앞선 대화의 목적지를 참고해 검색하며, 지역이 불분명하면 질문하도록 지시했습니다.
- 검색 결과를 번호 목록으로 표시하며 굵은 장소명 아래에 주소·분류·지도 링크를 배치합니다. 마지막에 영업시간·가격·휴무 확인 안내를 표시합니다.
- 최종 답변에는 마지막 도구 반환의 장소만 표시합니다. 앞선 검색 결과는 실행 기록에서 확인할 수 있습니다.
- 질문당 검색은 최대 3회이며 추천 결과는 항목별 최대 3곳입니다. 같은 장소는 중복 표시하지 않습니다. 검색 결과가 없거나 인증·권한·쿼터·네트워크 오류가 발생하면 안내합니다.
- 빈 결과일 때 모델이 다른 검색어로 도구를 다시 호출하며 순서를 기록합니다. 도구 내부의 자동 재검색은 끄므로 호출 한도와 실제 카카오 HTTP 요청 한도가 같습니다.
- IPO 명세에 따라 장소 검색 답변에는 실제 조회한 장소명·주소·분류·지도 링크만 표시합니다. 미조회 후보는 추가하지 않습니다.
- 도구 사용 시 OpenAI 추가 호출과 카카오 API 사용량이 발생합니다. 검색어는 카카오에, 반환된 장소 정보는 답변 작성을 위해 OpenAI에 전달합니다.
- 영업시간, 실시간 요금, 예약 가능 여부, 해외 장소, 길찾기와 이동시간 계산은 지원하지 않습니다. 국내 날씨는 아래 예보 조회로 지원합니다.
- `kakao_places.py`가 카카오 요청과 안전한 오류 처리를 담당합니다.

## IPO 실행 기록

실행 방식 선택 메뉴 없이 자동 실행하고, 답변 아래 ‘실행 결과 (IPO)’에 호출 횟수/한도·인자·status·반환 장소·실행 순서를 표시합니다.
챗봇이 자동으로 검색하며, 성공하면 종료하고 빈 결과일 때만 최대 3회까지 재검색합니다. 인증 등 오류에서는 중단합니다.
호출·반환·재검색·최종 답변 순서, 전환 사유, 도구명·인자·status·반환 장소는 대화 세션 내부에 보관합니다. 내부 사고 과정은 저장하지 않습니다.
최종 장소 안내는 마지막 도구 결과로만 만듭니다. 1회 종료·재검색 비교 함수는 코드 검증용으로 유지합니다.
지역, 장소 종류, 방문 조건을 구분해 기록하며 날짜 없이 장소를 검색합니다. 인사만 입력하면 장소 도구는 0회 호출됩니다.
기존 대화 기억·지도 링크·대화별 시간 표시를 유지합니다. 자세한 입력·처리·출력은 `IPO.md`를 참고하세요.
방문 조건은 API가 제공하는 필드 범위에서만 확인하며, 주차 등 미제공 정보는 확정하지 않습니다.

## 검색 정보로 여행 계획 추천

장소 검색 답변 아래 **검색 정보로 여행 계획 추천** 버튼을 누르면 기존 조회 기록을 우선 사용하고, 부족한 방문지·식당을 카카오에서 추가 검색해 계획 초안을 만듭니다.
계획에는 ‘방문 순서’ 번호 목록과 장소별 상세 주소·지도 링크, ‘제안: 오전 10시 방문’ 같은 시각 제안을 표시합니다. 별도 조회 사실 섹션과 날씨 표는 반복하지 않습니다.
준비물은 조회된 최고·최저기온과 강수확률에 따라 제안합니다. 날씨를 조회하지 않았으면 기본 준비물만 제안합니다.
‘준비물 / 제안’에는 비 가능성이 있으면 우산, 더운 날이면 물·모자·그늘 휴식 등 짧은 코멘트를 넣습니다. 예보 수치는 다시 나열하지 않습니다. 온열질환 예방 코멘트는 [CDC 안내](https://www.cdc.gov/extreme-heat/prevention/)를 참고했습니다.
영업시간·이동시간은 계획에 넣지 않으며, 방문 순서와 시간대는 일정 배치 초안입니다. 각 계획은 근거가 된 답변과 함께 세션에 보관합니다.
각 일차를 ‘오전 일정 / 점심 / 오후 일정 / 저녁’ 네 구간으로 구성합니다. 조회된 분류가 음식점인 장소만 식사 구간에 넣습니다. 하루 방문지 2곳·식당 2곳을 목표로 추가 검색하고, 중복은 제외합니다.
추가 검색은 여행 일수에 따라 최대 4~12회로 제한하며, API 사용량이 발생합니다. 분류·검색어·페이지를 바꿔 검색하고 인증·한도·연결 오류가 나면 중단합니다. 검색 후에도 후보가 부족하면 해당 구간을 비워 둡니다.
‘여행 계획 추가 검색 결과’에 추가 요청의 인자·상태·출처·조회 시각·반환 장소를 보관합니다. 기존 날씨·장소 실행 기록은 변경하지 않습니다.
‘3일 뒤 2박 3일’처럼 요청하면 출발일부터 3일간의 예보를 조회하고, 계획도 날짜가 붙은 1·2·3일차로 구분합니다. 장소 후보는 중복 없이 각 날짜에 나누며 부족한 날은 추가 검색이 필요하다고 안내합니다. 출발 날짜가 없더라도 명시한 여행 일수만큼 일차를 만듭니다.
날씨 좌표를 찾기 위해 조회한 장소는 관광 추천 장소로 사용하지 않습니다. 장소 추천 결과가 있어야 버튼이 표시됩니다.

검증: `.\.venv\Scripts\python.exe -m unittest discover -s tests -p test_travel_plan.py -v`

## 날씨 예보

- ‘경주 내일 날씨’, ‘부산 이번 주말 날씨’처럼 질문합니다. 상대 날짜는 한국 시간(Asia/Seoul)으로 해석합니다. 오늘·내일·모레·글피·N일 뒤·이번/다음 주말·요일과 YYYY-MM-DD, 월/일 표현을 지원합니다.
- 날짜가 없으면 날짜를 다시 묻습니다. 과거 날짜나 오늘부터 16일 범위 밖의 날짜는 **예보 없음**으로 표시하고 장소·날씨·모델 API를 호출하지 않습니다. 제목 요약 API도 생략합니다.
- ‘한달뒤’, ‘1개월 후’, ‘두 주 뒤’, ‘다음 달’, ‘내년’도 날짜로 인식합니다. 달·개월·년은 달력 기준으로 계산하고 월말은 해당 월의 마지막 날로 보정합니다.
- 조회 가능한 날짜는 카카오 장소 검색 결과의 x(경도), y(위도)를 그대로 Open-Meteo longitude, latitude에 연결합니다. 좌표가 없으면 임의 좌표로 대체하지 않습니다.
- 답변은 날짜(요일), 최고·최저 °C, 강수확률 % 표입니다. 강수확률은 일별 최대 강수확률이며 예보 기준 장소명을 명시합니다.
- 기록에는 두 도구의 인자·status·출처·조회 시각(+09:00)과 반환 값을 보관합니다. 호출하지 않은 요청은 조회 시각을 만들지 않고 사전 검사 시각과 retrieved_at=null을 남깁니다.
- 지원 범위 안에서도 응답에 날짜 자료가 없으면 ‘예보 없음’, 일부 값이 누락되면 ‘정보 없음’으로 표시합니다. 현재 날씨를 가져와 대신 채우거나 추가 조회하지 않습니다. 자료 누락 여부는 해당 API 응답 후에 확인됩니다.
- Open-Meteo 전용 키는 필요 없습니다. 좌표와 요청 날짜를 해당 서비스에 전송합니다. 지역이 명시되지 않으면 선택한 대화의 지역을 참고하거나 다시 질문합니다.
- ‘3일 뒤 경주 날씨랑 장소 추천해줘’처럼 복합 요청을 하면 날씨 작업(좌표 검색 → 예보 조회)과 장소 추천 검색을 별도 스레드로 병행합니다. 두 결과는 날씨·추천 장소로 구분해 표시하며 추천은 최대 3곳입니다. 기록에는 branch와 각 결과의 근거 호출 번호를 남깁니다. 날짜 사전 검사를 통과한 경우에만 병행 실행합니다.
- 답변 본문은 날씨와 장소 추천을 합친 하나의 글로 표시합니다. 본문 아래의 실행 결과 탭만 왼쪽 날씨 조회 / 오른쪽 지역·장소 검색을 같은 너비로 배치하며 기본적으로 접혀 있습니다.
- 기능은 독립적으로 동작합니다. 날짜가 없거나 범위 밖인 날씨 질문만 있으면 API를 호출하지 않습니다. 장소 추천을 함께 요청한 경우 날씨 API는 생략하고 장소 검색만 별도로 수행합니다.
- 날씨와 장소를 함께 조회한 뒤 ‘그럼 부산은?’, ‘서울로 바꿔줘’처럼 지역만 변경하면 기존에 해석한 날짜를 유지해 두 기능을 새 지역으로 다시 병행 조회합니다. 날짜가 지나도 상대 날짜를 다시 계산해 이동시키지 않습니다. ‘날씨는 빼고 장소만’ 요청은 해당 기능만 실행합니다.

## 시작 코드 반영 (2026-10-21)

제공된 `여행에이전트_시작코드.zip`의 현재 계획 저장, 재조사/로컬 수정 분리, 조회 근거 확인 개념을 기존 앱에 맞게 적용했습니다. 시작 코드의 단일 날짜 일정이나 순차 조회로 교체하지 않았습니다.

- `모레 경주에서 박물관 중심으로 하루 여행 계획을 만들어 줘`라고 요청하면 날씨·장소를 병행 조회하고 부족한 후보를 보충해 계획을 만듭니다. 날짜가 없으면 먼저 질문합니다.
- 기존 ‘검색 정보로 여행 계획 추천’ 버튼도 유지합니다. 생성된 계획은 대화별 ‘현재 여행 계획’으로 저장하며 버전과 조회 근거를 확인할 수 있습니다.
- `방문은 두 곳만, 오후 1시부터 5시까지로 바꿔 줘`처럼 방문 수·시간 범위를 바꾸면 재검색 없이 기존 후보로 조정합니다. 방문 수는 하루 기준이며 식사 장소를 포함합니다. `정확한 장소명 + 을 빼줘 / 다시 넣어줘`로 제외·복원할 수 있습니다. 모호한 이름과 적용 불가능한 조건은 기존 계획을 보존하고 안내합니다.
- ‘계획 조건 수정’에서 시간·방문 수·제외 장소를 직접 수정할 수도 있습니다. 주소·링크는 조회 결과에서만 사용합니다. 제안 시간은 영업시간·이동시간을 검증한 값이 아닙니다.
- 날짜·지역 변경은 날씨·장소를 다시 조회합니다. 변경하지 않은 방문 수·시간 범위는 유지하고, 지역이 바뀌면 이전 지역의 제외 목록을 적용하지 않습니다.
- 기존 대화 기록은 당시 결과의 스냅샷이며, 하단 현재 계획이 최신 버전입니다. 새 대화의 계획은 독립적입니다. 브라우저 세션 저장이므로 서버 재시작 시 사라집니다.

실행: `.\.venv\Scripts\python.exe -m streamlit run app.py`
검증: `.\.venv\Scripts\python.exe -m unittest discover -s tests`

참고: [Streamlit Session State](https://docs.streamlit.io/develop/api-reference/caching-and-state/st.session_state).


## 추천 장소 지도

추천 답변의 ‘추천 장소 지도 보기’, 여행 계획의 ‘여행 계획 상세 보기 → 추천 장소 지도’에서 Folium 지도를 표시합니다. 카카오 검색의 x(경도)·y(위도)를 지도용 위도·경도 순서로 변환하고, 여러 장소는 전체 좌표의 경계에 맞춰 중심과 확대 수준을 정합니다. 한 장소는 그 좌표를 중심으로 표시합니다. 좌표가 누락되거나 잘못된 장소는 제외 수를 안내하며 임의 좌표를 생성하지 않습니다.

번호 마커를 누르면 장소명·주소·카카오맵 링크를 볼 수 있습니다. 같은 위치의 마커는 클러스터를 확대해 확인할 수 있습니다. 계획을 수정하면 현재 방문지 목록만 지도에 반영합니다. 지도 조작으로 OpenAI·카카오 검색을 재호출하지 않습니다. 배경 지도는 OpenStreetMap 타일이며 표시할 때 브라우저의 네트워크 연결이 필요합니다.

참고: [Streamlit Folium 동적 지도 안내](https://discuss.streamlit.io/t/streamlit-folium-update-more-dynamic-maps/35149).
